# KhadSetu standalone Render MVP

KhadSetu is a farmer-to-depot fertilizer planning and allotment prototype. This folder is the independent Next.js app used for local PowerShell execution and Render deployment. It contains the complete demo flow: OCR soil report → farmer-verified readings → operator-reviewed product/rate → total kg and whole-bag suggestion → depot booking → token/OTP → farmer confirmation → operator redemption → stock decrement and audit.

## Quick start (Node.js 24.22.1.x)

From the repository root, run `..\run-render-mvp.ps1`, or directly:

```powershell
npm install
npm run dev
```

Open `http://localhost:3000`. For tests, run `npm run test:workflow`.

## Farmer workflow

1. Upload PDF or PNG/JPG/WEBP. PDF.js extracts selectable text; Tesseract.js reads scanned pages/images. English and English+Hindi modes are available.
2. Farmer checks/corrects N, P, K, organic carbon, pH and EC, adds crop and area and submits.
3. Operator inspects the readings and extracted text. Product rate must come from an appropriate crop/region/season guideline or agronomist; operator enters the rate, bag size, reference and acknowledgement.
4. The app calculates `area_ha = acres × 0.4046856422`, `product_kg = area_ha × rate_kg_per_ha`, and `bags_to_book = ceil(product_kg / bag_weight_kg)`.
5. Farmer books the complete bag count at a depot. Full stock reserves; shortage creates a FIFO waitlist. Booking receives a `KS-YYYY-xxxxxx` code; an OTP is issued only for reserved stock.
6. Farmer confirms a RESERVED token. Assigned depot operator redeems only a CONFIRMED token with matching OTP. Physical and reserved stock both decrement at successful redemption.

## Booking invariants

- No partial bag allotments.
- A soil report has at most one active RESERVED/WAITLISTED/CONFIRMED booking.
- Idempotent retries do not double-reserve.
- Reservations expire after 20 minutes if not fulfilled; expiry/cancellation releases stock.
- FIFO queue is by depot and product; do not skip an unsatisfied head request.
- Only OTP redemption decrements physical stock.
- Operator can reconcile physical counts but cannot count below active reservations.

## Deployment

At repository root, `render.yaml` is the fastest free temporary demo. `render.persistent.yaml` is the paid Starter single-instance demo with a 1 GB persistent disk. The service root is `render-mvp`; Render builds with `npm install --no-audit --no-fund && npm run build` and starts with `npm start`. `KHADSETU_SESSION_SECRET` is generated by Blueprint. No Figma OAuth/Payload credentials are required.

The JSON persistence store is single-instance and not transactional across multiple processes. Free Render filesystem is ephemeral. Production or multiple instances require managed PostgreSQL transaction/row-locking and real identity management.

## Model/data limitations

Model B remains untrained/unavailable in supplied project evidence. The application does not infer a fertilizer dose. Product/rate is operator-entered after checking an external source; quantity and bag suggestion are arithmetic. All demo depot inventory and user accounts are synthetic/public. Do not use real farmer PII, Aadhaar, government stock, real subsidy entitlements or this demo's quantities for agricultural advice.
